## Precise blocker

**CDP:** A **read-only inspection of `PYZ.pyz` inside the SHA-pinned, frozen EXE** found the compiled `webview.platforms.edgechromium.__init__` logic: `CoreWebView2CreationProperties.AdditionalBrowserArguments` is set to `--disable-features=ElasticOverscroll` and a `--remote-debugging-port=...` argument is appended **only when internal `webview_settings['REMOTE_DEBUGGING_PORT']` is not `None`**. The environment-only `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` requested by this QA harness was not observed in its WebView2 child process command lines; the private CDP port was not listening. Thus this frozen production executable was not CDP-attachable by that attempted method. The bytecode and runtime observations support this narrow explanation; they do not establish every possible WebView2 configuration or justify changing the frozen EXE.

**Private native accessibility:** A new non-input desktop process enumerated only the confirmed Taraz window and its owned child HWNDs. Five child windows were found, three with WebView-related classes. Four had UIA children. Its *actual owned P1 tab* exposed `InvokePattern` and was invoked successfully. Post-navigation three P1 strings/controls were found. The **help button** and **top menu button** also had exact accessible names, belonged to the owned PID tree, were enabled and had `ControlType.Button`, but neither exposed `InvokePattern`. A restricted, allowlisted `LegacyIAccessiblePattern` fallback did not open them. Therefore **Madar tab content is proven present in the compiled GUI**, but help/dialog dismissal, invoice designer, Sileo event feedback, and network leak claims remain unverified. No consent toggle, inbox read, external fetch, save or financial action was attempted.
