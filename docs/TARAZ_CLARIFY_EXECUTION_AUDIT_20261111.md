The audit metadata is a **read-only projection**, not a mutation of old event JSON, its SHA-256 hash chain or SQLite revision. It therefore works on historical accounting snapshots with existing replay semantics. `editedAt` means a content edit (`party.update`, `invoice.update`, `bill.update`), whereas `lastChangedAt` also includes other record transitions such as approval or issuance. Correction replacement IDs, converted proformas and contractor bills receive a creation attribution when their event creates the corresponding record.

The backend does not automatically repopulate party creator/editor fields from `currentUser`. Browser form-prefill behavior has a separate front-end implementation and was not fully covered by this worker's unit tests. The event-sourced attribution survives reload at the store level.

## Local model suggestion bridge

New `taraz_llm_order_suggest.py` exposes `suggest_order(text: str) -> dict` for the native authenticated `tarazOrderSuggest(requestText)` integration. It sends the user-initiated description only to `127.0.0.1:11434/api/generate`, with `format:"json"`, `stream:false`, `think:false`, `options:{temperature:0,num_predict:80,num_ctx:512}`, fixed local model `qwen3:4b`, strict 4,000-character input, 16 KB request cap, 24 KB response cap, 45-second socket timeout, credentials/contact redaction, and schema validation. The returned object contains only validated, user-grounded advisory order fields, allowed production stage names, missing fields and warnings. `source=LOCAL_OLLAMA` and `modelRan=true` appear **only** after a valid response from the local endpoint. There is no order creation, party creation, pricing write, financial event, external API URL or auto-application to the order form in this module.

`standalone_accounting_desktop.py` WebView allowlist now includes `tarazOrderSuggest` and `tarazPrintSuggest`. The prime agent owns the actual `TarazAPI` forwarders, UI wiring, packaging/import checks and build. A local-model suggestion pipeline is **not evidence of an autonomous AaaS agent**; orchestration, plans, tool-use and safe approvals would require additional reviewed behavior.
